## Ответы на контрольные вопросы

**1. Что разрешает политика AdministratorAccess? Почему для повседневной работы нельзя использовать root?**

Политика AdministratorAccess даёт полный доступ ко всем сервисам и ресурсам AWS-аккаунта, включая управление пользователями и их правами. Root-пользователь — это владелец аккаунта, и компрометация его данных означает полную потерю контроля над аккаунтом, включая биллинг. Для повседневной работы используют IAM-пользователей, чтобы можно было отзывать доступ, ограничивать права и отслеживать действия конкретного человека, не трогая root.

**2. Что такое User data и когда выполняется этот скрипт? Выполнится ли он повторно после перезагрузки экземпляра?**

User Data — это скрипт, который AWS передаёт экземпляру при его первом запуске, и он выполняется автоматически от имени root при самой первой загрузке операционной системы. После обычной перезагрузки скрипт повторно не выполняется — только при первом старте экземпляра после создания. Это позволяет автоматизировать первоначальную настройку сервера без ручного вмешательства.

**3. Какая из проверок укажет на проблему, которую можете исправить вы, а какая на проблему на стороне AWS?**

System status check указывает на проблему инфраструктуры AWS (физический сервер, сеть) — это зона ответственности AWS. Instance status check и Attached EBS status check чаще указывают на проблемы, которые можно исправить самостоятельно — например, неправильная конфигурация ОС, упавшие сервисы или проблемы с файловой системой тома.

**4. В каких случаях стоит включать детальный мониторинг?**

Детальный мониторинг стоит включать, когда нужно быстро реагировать на изменения нагрузки, например для автоматического масштабирования с минимальной задержкой реакции. Также он полезен при отладке производительности и диагностике кратковременных всплесков нагрузки. Для простого сервера с предсказуемой нагрузкой базового мониторинга обычно достаточно.

**5. Почему для входа на экземпляр EC2 используется ключ, а не пароль?**

Ключевая пара значительно надёжнее пароля — её практически невозможно подобрать перебором. Приватный ключ никогда не передаётся по сети даже при подключении, в отличие от пароля. Это также удобнее для автоматизации при массовом развёртывании серверов.

**6. Что делает команда scp и чем она похожа на ssh?**

scp копирует файлы между локальным компьютером и удалённым сервером через зашифрованное соединение. Она похожа на ssh тем, что использует тот же протокол и тот же механизм аутентификации — тот же приватный ключ и имя пользователя. По сути, scp — это ssh для передачи файлов, а не для интерактивной сессии.

**7. Чем Stop отличается от Terminate? За что вы продолжаете платить, пока экземпляр остановлен?**

Stop останавливает экземпляр, но сохраняет его диски и настройки — его можно запустить снова без потери данных. Terminate полностью удаляет экземпляр и привязанные к нему тома — восстановить его нельзя. Пока экземпляр в состоянии Stop, вы не платите за вычислительные часы, но продолжаете платить за хранение присоединённых томов EBS и за Elastic IP, если он закреплён за экземпляром.
