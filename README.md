## Ответы на контрольные вопросы

### Задание 1

**Почему доступных адресов не 256? Какие адреса подсети 10.X.0.0/24 занимает AWS и для чего? Сколько ещё подсетей /24 поместится в вашу VPC?**

В каждой подсети AWS резервирует пять адресов, поэтому из 256 экземплярам остаётся 251. В подсети 10.X.0.0/24 это: 10.X.0.0 (адрес сети), 10.X.0.1 (виртуальный маршрутизатор VPC), 10.X.0.2 (DNS-сервер VPC), 10.X.0.3 (резерв AWS на будущее) и 10.X.0.255 (широковещательный адрес, который в VPC не поддерживается, но всё равно зарезервирован). В VPC 10.X.0.0/16 помещается 256 подсетей /24, четыре из них уже созданы, значит, можно создать ещё 252.

### Задание 2

**Является ли подсеть public-a сейчас публичной? Почему?**

Нет. Подсеть считается публичной не по названию, а по наличию маршрута в Internet Gateway. Сейчас Internet Gateway ещё не создан, а в таблице маршрутов подсети есть только локальный маршрут внутри VPC, так что выхода в интернет нет.

### Задание 3

**Какой маршрут есть в обеих таблицах, хотя вы его не добавляли? Что он даёт? Куда уйдёт пакет из private-a, адресованный 8.8.8.8?**

В обеих таблицах есть локальный маршрут `10.X.0.0/16 → local`, который AWS добавляет автоматически. Он обеспечивает связь между всеми подсетями и серверами внутри VPC независимо от зоны доступности. Пакет из private-a на 8.8.8.8 никуда не уйдёт: адрес не входит в 10.X.0.0/16, а маршрута `0.0.0.0/0` в private-rt нет, поэтому пакет будет отброшен.

### Задание 4

**Почему в db-sg источником указана группа web-sg, а не адрес веб-сервера или диапазон 10.X.0.0/16?**

Группа в качестве источника следует за самими серверами: если веб-сервер заменят или его адрес изменится, правило продолжит работать без правок. Диапазон 10.X.0.0/16 пустил бы к базе вообще любой сервер VPC, включая bastion, а это нарушает принцип минимальных привилегий. Привязка к группе даёт доступ только тем экземплярам, которым он действительно нужен.

### Задание 5

**Почему db-server не может скачать пакеты, хотя web-server это делает? Что нужно добавить в сеть, чтобы это стало возможно, и при этом db-server остался недоступным из интернета?**

У db-server нет публичного адреса, а в private-rt нет маршрута в интернет, поэтому запросы за пакетами некуда отправлять. Нужен NAT Gateway в публичной подсети и маршрут `0.0.0.0/0 → NAT Gateway` в private-rt. NAT пропускает только исходящие соединения, начатые изнутри, а у сервера по-прежнему нет публичного адреса, поэтому из интернета к нему подключиться нельзя.

### Задание 6

**Какой адрес вернула команда checkip? Сравните его с Elastic IP NAT Gateway. Почему это не адрес db-server?**

Команда вернула адрес, который совпадает с Elastic IP NAT Gateway _[проверьте и впишите свой адрес]_. У db-server есть только приватный адрес, поэтому NAT Gateway подменяет его в исходящих пакетах на свой Elastic IP. Для внешнего мира все серверы приватной подсети выглядят как один адрес NAT Gateway.

**Доступ к базе ограничивают три механизма. Что делает каждый из них? Что произойдёт, если ошибиться только в одном?**

Первый механизм сетевой: у db-server нет публичного адреса и нет маршрута в Internet Gateway, так что из интернета до него просто не добраться. Второй механизм это Security Group db-sg, которая пропускает порт 5432 только от web-sg. Третий это `pg_hba.conf`, который внутри PostgreSQL разрешает вход только с адресов 10.X.0.0/24 и по паролю. Это многоуровневая защита: если ошибиться в одном слое (например, случайно открыть db-sg для всех), остальные слои всё равно не дадут подключиться.

**Почему PostgreSQL продолжает работать после удаления NAT Gateway? Что придётся сделать, когда понадобится установить обновления безопасности?**

PostgreSQL уже установлен на диске и работает локально, ему интернет нужен только на этапе скачивания пакетов. Для обновлений безопасности придётся снова создать NAT Gateway, добавить маршрут `0.0.0.0/0` в private-rt, установить обновления, а затем удалить шлюз и маршрут.

### Задание 7

**Почему с web-server порт 5432 открыт, а с bastion нет, хотя оба сервера в одной VPC и маршрут между ними есть?**

Маршрутизация лишь позволяет пакетам дойти до сервера, а решение о пропуске принимает Security Group. В db-sg порт 5432 разрешён только для источника web-sg, а bastion входит в bastion-sg, поэтому его соединение молча отбрасывается и по таймауту выглядит как closed.

**Почему запрос curl с db-server не проходит? Можно ли из интернета подключиться к порту 5432 db-server? Объясните по цепочке: маршрут, адрес, фильтры.**

Запрос не проходит, потому что в private-rt нет маршрута `0.0.0.0/0` (после удаления NAT Gateway) и у сервера нет публичного адреса. Из интернета подключиться к порту 5432 нельзя. Маршрут: в подсети private-a нет пути в Internet Gateway. Адрес: у сервера только приватный адрес 10.X.10.x, который в интернете не маршрутизируется. Фильтры: даже если бы пакет дошёл, его остановили бы db-sg и `pg_hba.conf`.

**Почему заблокировано и SSH, и сайт, хотя вы не меняли ни одной Security Group? Почему с телефона сайт открывается? Почему правило должно иметь номер меньше 100?**

Network ACL работает на границе подсети и проверяет трафик до Security Group. Default NACL связан с обеими публичными подсетями (public-a и public-b), поэтому правило Deny для моего IP блокирует весь трафик с него: и SSH на bastion, и HTTP на web-server. С телефона по мобильному интернету у меня другой IP, под правило он не попадает и проходит по разрешающему правилу. Правила NACL проверяются по возрастанию номера, и сработавшее первым правило применяется сразу; стандартное разрешающее правило имеет номер 100, поэтому Deny с номером 90 должно оказаться раньше него.

**Как по тегам найти все ресурсы, которые нужно удалить после окончания проекта? Зачем нужен тег Owner, если аккаунт у вас личный?**

В Tag Editor нужно выбрать регион, тип ресурсов All supported resource types и тег `Project = timecapsule` (при необходимости добавить `Lab = lab3`): в списке окажутся все ресурсы проекта, и их можно удалять по очереди. Тег Owner нужен потому, что в рабочих аккаунтах ресурсами пользуются многие и по тегу видно, кого спросить, можно ли удалять ресурс. Привычку ставить Owner полезно выработать заранее, да и преподаватель по нему сразу видит, чьи это ресурсы.
