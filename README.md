## Ответы на контрольные вопросы

### Задание 1

**Какой ключ у картинки? Почему Object URL не открывается, хотя вы владелец бакета? Что на самом деле создала кнопка Create folder?**

Ключ картинки состоит из префикса и имени файла, например `uploads/image.jpg` _[впишите свой]_. В S3 нет настоящих папок, `uploads/` это лишь часть ключа. Object URL не открывается, потому что бакет закрыт для публичного доступа (Block all public access), а при открытии ссылки в браузере запрос приходит анонимным, без подписи. Права владельца действуют только для запросов, подписанных его учётными данными. Кнопка Create folder создала пустой объект нулевого размера с ключом, оканчивающимся на `/` (например, `uploads/`), который консоль показывает как папку.

### Задание 2

**Почему первая команда ls показывает PRE uploads/ и PRE backups/, а третья показывает полные ключи? Какой Content-Type получил report.txt, хотя вы его не указывали?**

Без `--recursive` команда `ls` группирует ключи по разделителю `/` и показывает только верхний уровень: общие префиксы помечаются как `PRE`. С параметром `--recursive` она выводит все ключи плоским списком, без группировки. Content-Type у `report.txt` стал `text/plain`: AWS CLI определяет тип по расширению файла, если тип не задан явно _[проверьте в выводе head-object]_.

### Задание 3

**Почему вторая команда получает AccessDenied, хотя у вас права администратора? Почему Block Public Access не помешал сохранить политику с "Principal": "*"?**

В политике бакета стоит явный запрет (Deny) для запросов по HTTP (`aws:SecureTransport = false`), а явный запрет в AWS всегда сильнее любых разрешений, в том числе администраторских. Block Public Access блокирует политики, которые открывают бакет для всех (разрешающие `Allow`). Наша политика, наоборот, запрещает доступ, поэтому публичный доступ не расширяет, и сохранение не блокируется.

### Задание 4

**Чем удаление в шаге 3 отличается от удаления в шаге 5? Какое из них можно отменить? Какой из двух способов защищает от случайного удаления, а какой нужно запрещать приложению?**

В шаге 3 мы удаляли объект без указания версии, и S3 лишь добавил маркер удаления (Delete marker), а все версии данных остались на месте. В шаге 5 мы удалили конкретную версию по её идентификатору, и такое удаление окончательное. Отменить можно первое: достаточно удалить маркер, и объект вернётся. От случайного удаления защищает первый способ, а удаление конкретных версий нужно запрещать приложению, иначе оно сможет уничтожить историю.

### Задание 5

**Как поведёт себя правило для файла, который перезаписывали 10 раз за неделю? Какие версии и когда окажутся в Standard-IA, какие будут удалены? Почему наши маленькие тестовые файлы в Standard-IA не попадут? Что такое незавершённая загрузка частями и почему за неё приходится платить?**

После 10 перезаписей останется одна текущая версия и 9 неактуальных. Отсчёт для каждой неактуальной версии идёт с момента, когда её заменила более новая. Через 30 дней такие версии перейдут в Standard-IA, а через 90 дней будут удалены все неактуальные версии, кроме двух самых новых. Текущая версия правилом не затрагивается. Маленькие тестовые файлы не попадут в Standard-IA, потому что S3 не переводит в этот класс объекты меньше 128 КБ (это невыгодно из-за минимального оплачиваемого размера). Незавершённая загрузка частями возникает, когда большой файл начали загружать по частям, но не завершили и не отменили. Уже загруженные части лежат в бакете невидимыми в списке объектов и оплачиваются как обычное хранение, а правило через 7 дней их удаляет.

### Задание 6

**Какие ошибки вернул S3 в шагах 3 и 4? Почему нельзя получить другой файл, просто поменяв ключ в ссылке? Обращалась ли команда aws s3 presign к S3, когда создавала ссылку?**

В шаге 3 (подменённый ключ) S3 вернул ошибку `SignatureDoesNotMatch`, в шаге 4 (просроченная ссылка) ошибку `AccessDenied` с сообщением `Request has expired` _[сверьте с вашими скриншотами]_. Ключ нельзя поменять, потому что подпись вычисляется от всего запроса, включая путь к объекту, и при любом изменении ссылки подпись перестаёт совпадать. Команда `aws s3 presign` к S3 не обращалась: ссылка подписывается локально учётными данными, без сетевого запроса. Объект при этом проверяется только в момент открытия ссылки.
